現場重跑

按一次就在瀏覽器裡跑三個指定情境與 25 個回歸案例。結果來自 ossReliability.js，與 npm run oss-demo 同一組規則。

1. 未核准不能發布

2. 不確定狀態重試不能重複發布

3. 缺少分析資料不能當成零

    這份示範在證明什麼

    不是「洗衣店自動發文很好用」，而是其他開發者能在乾淨環境檢查這三條正式環境規則：

    • 核准完整性：缺少核准、強制核准、店休，或核准後指紋對不上，模擬平台呼叫次數必須是 0。
    • 重試與不確定狀態：送出後回應遺失記成 uncertain，再跑一次不得新增遠端貼文。
    • 分析缺失：未設定、讀取失敗或空資料集維持 unmeasured，數字欄位缺席，不能寫 0。

    軟體是 MIT；店家照片、品牌與客人資料不是。授權切分見 repository 的 LICENSE 與 NOTICE。
